# Corpus - the raw reference reels

Source material, stored verbatim. `frameworks.md`, `hooks.md` and `visual-craft.md` are the compression of this file; this file is the thing they were compressed from. Keep both - a mechanism write-up cannot be re-derived once the original is gone.

**Read before Mode 4.** Before writing up any new framework, check here for whether the mechanism already exists under a different subject.

## Ingestion rules

1. Raw entry goes in **before** any analysis. Transcribe first, autopsy second.
2. Classify against F1-F8 assuming **skin by default**. The bar for a new framework is a different structural spine, an ending style not in the existing set, or a follow trigger the corpus does not cover. Different subject matter is not a new framework.
3. A reel that contributes nothing to `frameworks.md` can still be worth ingesting for one hook mechanic or one text treatment. Harvest those into `hooks.md` / `visual-craft.md` separately.
4. **Views are not the target.** Per performance-log E2 and E3, transmissible-fact reels reliably win reach and have not yet converted a follower. If this corpus gets weighted by view count the skill will drift toward reach mechanics and away from the identity payload the Kill Test requires. Every entry must answer FOLLOW TRIGGER honestly, and "nothing, it is just very shareable" is a valid and useful answer - that reel then informs hooks and visual craft only, never framework selection.
5. Contradictions get flagged, not merged. If a huge reel breaks a hard rule, note it here; do not quietly loosen the rule.

```
- the turn:
- ending style:
- FOLLOW TRIGGER: what makes a stranger want the next chapter of this person

- CLASSIFICATION: skin on F_ / new mechanism because ___
```

Note: full metric data (views/saves/follower delta) lives in the reel-database Google Sheet, not here. These entries carry the sheet's short description, the transcript and the autopsy. When a reel's real numbers are known, add them to NUMBERS.
