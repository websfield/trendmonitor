## 3. Patterns the remedies reuse (no new abstractions needed)

The audit's own conclusion is that the answer is a derived population, not a longer hand list, and that `traceability.ts` is the template. It is, and it is reusable as-is:

1. **The generative witness** — `packages/modes/tests/traceability.test.ts:697-826`. Deterministic LCG seeded by a date literal (`:698-707`); hand-written vocabularies, not a fuzzer (`:709-770`); the property expressed over **character spans**, not tokens (`:772-784`); **the population derived from the module** — `SPECIFIC_SHAPES.filter(s => s.enforcement === "hard").map(s => s.id)` (`:786-788`); the seed in the assertion label (`:818`); and **two-way non-vacuity** — the generator really produces refusable drafts *and* every shape in the module was exercised (`:820-826`). This is the shape Phase 2's claims generator copies.
2. **The R-121 presenter substitution** — `packages/credits/src/sample-spin/run.ts:363-372`: derive the display set from `outputTextUnits`, `.filter(u => !u.field.startsWith("/disclosure/"))`, and return the neutral `disclosure: { kind: "policy_check_required" }`. Both non-compliant presenters get this, and `displayableSpin`'s hand-written five-of-ten field list (`trends/actions.ts:36-42`) gets the same derivation, closing two findings with one mechanism.
3. **The on-disk population assertion** — `no-scraping.test.ts:106-111` already proves its *package* list against `readdirSync`. The same four lines applied to a shared roots module answer items 13, 14 and R2-2 together.
4. **The compiled input bound** — `sample-spin/run.ts:81-83` `tokenUpperBound = Buffer.byteLength(text,"utf8")` against a compiled constant, with the docblock rule "runtime config may only tighten". `worker/autopsy-vendor.ts:139-143` is the same computation inline. The tenant path needs this constant, not a new config surface. *(**Superseded 2026-09-21** by Phase 3 P3-R2, on the batch-0 billing gate's BLOCK: the tenant ceiling is a **config key**, `llm.maxInputTokens`, seeded in `CONFIG_V1_SEED` and listed in the `llm` object-level default — the gate's own precedent is `frameworkContextCharBudget` (`schema.ts:366-375`, "IT IS A SPEND DIAL, WHICH IS WHY IT IS NOT A CONSTANT"), and input is billed per token, so the number is a REQ-G05 margin input. The computation reused is still this one; the two R-123 public-path ceilings stay compiled and config may only tighten them. The sentence above is kept as this review's original recommendation, not deleted.)*
5. **The in-file bookkeeping guard** — `generate.ts:1230-1250` already wraps `recordUsage` and carries the bookkeeping failure on `e.cause`. D3's fix is to mirror the pattern eleven lines down, not to invent one.
6. **The brand** — `VerifiedWorkspaceId` is the existing pattern item 40 asks for on entitlements.

**What does not exist and must be built:** a shared `tests/support` roots module; a shared claim-scan helper; a shared sentence-separator constant; a non-blocking workspace-lock read (`takeWorkspaceLock` at `clock.ts:67-76` is `pg_advisory_xact_lock`, blocking-only; **`lock_timeout` appears nowhere in the tree**); any contrast-ratio computation (**no luminance or WCAG arithmetic exists anywhere in `respin/tests`**); and an episode-start column on `subscriptions`.

- **Deploy-side work is not in any phase.** Per the owner's 2026-09-19 decision (`todos.md` T-19/T-20), items whose closure needs a cloud account, a provisioned bucket, a real deploy or a paging integration go to `todos.md` as new rows. - **Item 39 (`@respin/db` is domain + infrastructure) is scoped to its doc half.** Carving `@respin/telemetry` and `@respin/lifecycle` out of a 46,107-line package is a refactor with a large blast radius and no live defect behind it; what is live is that `tech-spec.md:34-35` describes a package map that does not exist. The plan fixes the document, records the carve as a decision with a revisit trigger, and does not move code.
- **Item 9's refund-budget row is out of scope by the audit's own words** — "confirming it is still exactly as its own docblock records, not re-reporting it as new."
- **The unswept list is not remediation.** `packages/db/src/{deletion-executor,retention-clocks,retention-receiver,auth-lifecycle}.ts`, `packages/brain/src/{comparison,vocabulary}.ts`, the worker job payloads and the `packages/modes` test files round 3 could not reach were read by nobody.
