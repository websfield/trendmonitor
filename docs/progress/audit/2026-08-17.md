# Audit register — 2026-08-17

**Scope:** the up-to-date Respin implementation (`respin/`, `docs/initial/`), plus a revisit of `NORTH_STAR.md` for drift. Two earlier product lines (`src/` UGC Intelligence, `cutdown/`) are out of scope — untouched by this run.

**Build state at time of audit:** M0 + M1 (Stripe billing, append-only credit ledger) complete 2026-08-17, both Critical-Path gates PASS (Ready, A/A) per `docs/progress/respin-m1-review.md`. The working tree carried uncommitted post-evidence-run fixes on top of commit `451d0d2` (the `cancel_at` mirror fix). M2 (brain/onboarding) is next and not yet built.

**Readiness headline: Not yet — grade C+.** The engineering discipline here is unusually strong (structural tenancy cage, import-boundary enforcement, extensive money-path test coverage, self-aware docs that name their own gaps) — but that discipline has a hole: the pause invariant (REQ-G08, "no charges, no monthly grants while paused") is violated by two independent, verified code paths, the webhook mirror-write pattern has a systemic unlocked-race shape that two independent reviewers (a Claude depth read and Codex, unprompted) converged on line-for-line, and the one dataset that is literally money has never been backed up or restored. None of these are hard to fix; none of them are fixed yet.

**Rounds run:** 1 full round (8 track critics + 2 Respin-specific gate seats + outside voice + 5-artifact depth room), all dispatched from the audit's own posture brief. No second round was dispatched — every hunch and every Codex claim was chased and resolved (promoted or dismissed) by the chair directly rather than needing a fresh critic pass; nothing chased opened a new unresolved lead. Outside voice: **ran** (Codex, `model_reasoning_effort=high`, scoped to Respin) — 6 P1 + 3 P2, all six P1s independently verified by the chair against source, two of them (mirror TOCTOU race, dead-subscription pause-mirror drift) cross-confirmed by the Claude depth room finding the identical lines independently.

## Ranked register

### Billing & credits (money-path)

1. **[HIGH] billing — a paused workspace can still be charged for a credit pack.** `createPackCheckoutUrl` (`respin/packages/credits/src/stripe/actions.ts:271-294`) and its caller `buyPackAction` (`respin/app/(product)/settings/billing/actions.ts:110-125`) call `assertOwner` only — no `pausedAt` check — before creating a real, payable Stripe Checkout session. The sibling `auto-topup.ts:80` guards the identical hazard (`if (sub.pausedAt !== null) return {triggered:false, reason:"paused"}`); this path doesn't. The billing page's own copy asserts "No charges while paused" two components away (`billing-view.tsx:414`). Violates REQ-G08 ("Must"). *Evidence: `respin-invariant-drift-critic` finding 1, independently re-verified by chair (actions.ts:271-294 read directly, confirmed no pause read).* **Fix:** add the same guard `auto-topup.ts` uses; disable the "Buy pack" control in the UI when paused; add an isolation test pinning it. **Owner:** respin-engineer.

2. **[HIGH] billing — `invoice.paid` grants the monthly credit allowance even while the workspace is paused, and a test deliberately locks this in.** `respin/packages/credits/src/stripe/webhooks.ts:639-641` processes `invoice.paid` with no pause check; `respin/packages/credits/tests/stripe.test.ts:630-641` is titled *"invoice.paid arriving while mirror-paused is PROCESSED... never dropped"* and asserts a grant lands. REQ-G08 (`docs/initial/PRD.md:118`, "Must"): "While paused: no charges, no monthly grants." *Evidence: Codex (outside voice) [P1], independently verified by chair — read the handler, read the test, read the PRD line.* The code's own implicit rationale ("a paid invoice is a fact, don't drop the money") is defensible engineering for a genuine race, but it isn't written down anywhere as an accepted exception to a "Must" requirement — right now it just reads as REQ-G08 being false. **Fix:** either make this narrow race explicit (log + a decisions.md entry naming it as an accepted exception with the reasoning), or refuse the grant and route the invoice to a manual-reconciliation path. **Owner:** respin-engineer + product decision on which remedy.

3. **[HIGH] billing — every `subscriptions`-mirror webhook writer is an unlocked read-then-write; concurrent or out-of-order Stripe deliveries can silently revert newer billing state to stale.** None of the five mirror writers (`checkout.session.completed`, `customer.subscription.created/updated`, `customer.subscription.deleted`, `invoice.paid`, `invoice.payment_failed` — `webhooks.ts:403-847`) take `takeWorkspaceLock` or use a compare-and-set `WHERE`; each reads the mirror, checks staleness against *that* snapshot, then does a plain `.update()`. The credit ledger itself was already proven unsafe under exactly this shape and fixed with `takeWorkspaceLock` (`clock.ts:30-53`, "11 of 20 concurrent debits succeeded against a 100 balance") — the fix was never carried over to this file. One concrete instance already confirmed independently: `invoice.paid`'s grace-clear (`webhooks.ts:800-809`) nulls `graceExpiresAt` without gating on the same `invoiceMayWriteStatus` staleness guard its own status-lift half uses, so a stale, out-of-order `invoice.paid` can end a *currently live* dunning grace early with nothing left to correct it. *Evidence: `correctness-critic` finding 1 (the graceExpiresAt instance) + `depth-webhooks` finding 1 (the systemic pattern across all 5 writers, `(cross-critic)`) + Codex [P1] on the identical lines (`webhooks.ts:451-459,520-563,604-636`) `(outside-voice, cross-critic)` — three independent reviews, two different models, converging on the same lines.* No concurrent-differing-payload test exists (`concurrency.docker.test.ts:488-571` only exercises identical concurrent payloads, which idempotency masks). **Fix:** wrap each mirror writer in `takeWorkspaceLock`, or make the `UPDATE`'s `WHERE` a compare-and-set against the watermark being replaced; add a differential-payload concurrency test. **Owner:** respin-engineer.

4. **[HIGH] billing — invoice events are scoped only by workspace/customer, never cross-checked against which subscription actually generated them; a stale invoice from a superseded subscription can misapply to the current one.** `invoice.paid` (`webhooks.ts:655-700`) and `invoice.payment_failed` (`webhooks.ts:814-847`) both resolve the mirror by `eq(subscriptions.workspaceId, workspaceId)` alone — neither compares the invoice's own subscription id against `mirror.stripeSubscriptionId`. A workspace that cancels and resubscribes gets one new mirror row; a late-arriving invoice event tied to the *old*, now-dead subscription has no id check stopping it from granting credits or pushing the *new* subscription into dunning. This is the same defect class the M1 review already found and fixed once for checkout events ("a resurrection hazard where a re-subscribe checkout event could permanently orphan the mirror onto a dead subscription id," round 5b) — the fix didn't extend to the invoice handlers. *Evidence: Codex [P1], independently verified by chair (read both handlers, confirmed no subscription-id comparison exists anywhere in either).* **Fix:** compare `invoice`'s subscription id against `mirror.stripeSubscriptionId` before writing; `ignore` on mismatch. **Owner:** respin-engineer.

5. **[HIGH] billing — dead-subscription cleanup never clears `pausedAt`/`resumesAt`; a mirror that drifts into "paused with no open pause period" and then cancels can render as permanently paused-with-a-stale-paid-tier.** `DEAD_SUBSCRIPTION_FIELDS` (`webhooks.ts:139-148`, applied on every irreversible-status write) omits `pausedAt`/`resumesAt`/`stripePriceId`; `customer.subscription.deleted`'s call to `ensurePauseEnded` (`webhooks.ts:621`) is a no-op when no open `pause_periods` row exists — a drift state `pause.ts:172-187`'s own docblock concedes is reachable ("the owner's resume path could reach a state where the two truths disagreed"). `state.ts:124` trusts `sub.pausedAt !== null` unconditionally, *ahead of* any status/liveness check — the one branch in that file that skips the liveness-gate discipline every other branch uses. Net effect: a canceled subscription in this drifted state renders `{state: "paused", resumesAt: <stale date>, tier: <stale paid tier>}` forever. *Evidence: `depth-state` finding 1 (full derivation, confirmed untested — `state.test.ts` has no case combining `status:"canceled"` with `pausedAt` set) + Codex [P1] on the same webhooks.ts/state.ts lines `(outside-voice, cross-critic)`.* **Fix:** extend `DEAD_SUBSCRIPTION_FIELDS` to clear `pausedAt`/`resumesAt`; add a liveness gate to `state.ts`'s paused branch matching the pattern `scheduledCancelAt` already uses. **Owner:** respin-engineer.

6. **[MEDIUM] billing — an `unpaid` subscription keeps auto-top-up's off-session charging authority armed.** `DEAD_SUBSCRIPTION_FIELDS` clears on `IRREVERSIBLE_STATUSES` (`canceled`, `incomplete_expired`) but auto-top-up fields need the broader `TERMINAL_STATUSES` (which also has `unpaid`, deliberately excluded from `IRREVERSIBLE_STATUSES` so the sub stays dunning-recoverable). `maybeAutoTopup` (`auto-topup.ts:76-78`) reads `unpaid` as "live" and would attempt an off-session charge for a workspace `getWorkspaceBillingState` already shows as `free`. *Evidence: `correctness-critic` finding 2 + `depth-webhooks` finding 2 `(cross-critic)`.* Not exploitable yet — M1 has no debit call site, so nothing triggers `maybeAutoTopup` today; this is a landmine for M3. **Fix:** clear only `autoTopupEnabled`/`autoTopupMonthlyCapCents` on `TERMINAL_STATUSES`, or have `maybeAutoTopup` refuse on it directly. **Owner:** respin-engineer, before M3.

7. **[MEDIUM] billing — manual pack price and auto-top-up pack price can silently diverge.** Manual `createPackCheckoutUrl` (`actions.ts:271-294`) charges Stripe's immutable `Price` object via `stripePriceMap`; `maybeAutoTopup` (`auto-topup.ts:86,119-129`) charges `Math.round(content.pack.priceUsd * 100)` as a raw `PaymentIntent` amount, independent of any Stripe Price. An admin editing `pack.priceUsd` in `/admin/config` (append-only, no deploy needed) takes effect on auto-top-up immediately while the manual Checkout price stays whatever `stripePriceMap` was last `stripe:setup`-synced to — same credits, two live prices, until someone remembers to rerun setup. *Evidence: Codex [P1], verified by chair (read both charge sites, confirmed no shared source of truth).* **Fix:** derive both charge paths from the same value, or validate at config-write time that `pack.priceUsd` matches the live Stripe Price. **Owner:** respin-engineer.

8. **[MEDIUM] billing — `incomplete` subscriptions are treated as "live" for duplicate-checkout prevention but render as Free tier with no actionable recovery.** `hasLiveStripeSubscription` (`state.ts:39-46`) excludes only `IRREVERSIBLE_STATUSES`, so `incomplete` counts as live and blocks a second Subscribe attempt (`page.tsx:61-63`) — but `getWorkspaceBillingState`'s status switch has no `incomplete` branch and falls through to Free (confirmed via `depth-state`'s independent hunch on the identical fall-through pattern for `unpaid`). The UI hides Subscribe and offers only the Customer Portal, which cannot resolve a subscription that never activated. A failed/SCA-required first payment leaves the customer stuck. *Evidence: Codex [P1], verified by chair.* **Fix:** give `incomplete` its own UI state with a real remedy (retry payment / start a fresh checkout after canceling the incomplete one). **Owner:** respin-engineer.

### Operability

9. **[CRITICAL] ops — no backup exists, and none has ever been restored, for the one dataset that is money.** `RUNBOOK.md:13` says so itself; confirmed in code — `docker-compose.yml` defines only a throwaway dev volume, no backup tooling exists anywhere under `respin/`. *Evidence: `operability-critic` finding 1.* **Fix:** stand up real Postgres backups before the first production deploy and run one documented restore drill. **Owner:** whoever owns the Lightsail deploy plan.

10. **[HIGH] ops — DB migration rollback is named in the runbook but has no executable mechanism.** No `db:rollback`/`down` script exists; migrations are forward-only SQL. `RUNBOOK.md:10`'s "planned" rollback names no real command. *Evidence: `operability-critic` finding 2, corroborated by `depth-runbook`.* **Fix:** either adopt reversible migrations with a real script, or replace the claim with "rollback = restore from backup" (only once finding 9 is closed). **Owner:** respin-engineer.

11. **[HIGH] ops — the Respin quick-start in RUNBOOK.md does not work as written.** No step sets `DATABASE_URL`; `db:migrate`/`db:seed` are drizzle-kit/tsx processes that don't read `.env.local` (only Next does) — `respin/README.md:42-49` names this exact trap and the fix, but `RUNBOOK.md:7`'s condensed command chain omits it, so a stranger following only RUNBOOK.md fails at the first DB step. *Evidence: `depth-runbook` finding 1 — a defect the operability-critic's first pass, working from the same file, did not catch; found only on the line-by-line depth re-read.* **Fix:** inline the `DATABASE_URL=...` prefix into RUNBOOK's Respin quick-start, or point directly to the README section. **Owner:** whoever owns RUNBOOK.md (`/sync-docs` can mechanically fix this).

12. **[LOW] ops — RUNBOOK's own "## Rollback" section contradicts itself within four lines** (line 99 "None found — no deploy surface" vs. lines 104-110, a complete, currently-runnable three-step UGC rollback procedure copied under a heading that says none exists). *Evidence: `depth-runbook` finding 2.* **Fix:** the "None found" line belongs only in the Respin section it was copied from. **Owner:** `/sync-docs`.

13. **[LOW] ops — RUNBOOK's generic section headings (`## Deploy`, `## Rollback`, etc.) don't repeat the "UGC-only" qualifier stated once in the intro,** inviting a reader to misapply parked UGC instructions to the active, money-bearing Respin system. *Evidence: `depth-runbook` finding 3.* **Fix:** tag each heading `(UGC Intelligence only)`. **Owner:** `/sync-docs`.

14. **[LOW] ops — RUNBOOK's Accounts "Last reviewed" date is already stale relative to a row edited after that date** (header says 2026-08-14; the Stripe row cites a 2026-08-17 doc). *Evidence: `operability-critic` finding 3.* **Fix:** bump the date on every Accounts edit, not just dedicated review passes.

### Accessibility

15. **[HIGH] a11y — sign-in/sign-up fields have no visible label, only placeholder text that disappears on input.** `respin/app/(auth)/auth-form.tsx:42-66` — `aria-label` only, no `<label>`; the 8-character password minimum is enforced but never shown. WCAG 3.3.2 (Level A) on the product's only entry point. *Evidence: `accessibility-critic` finding 1.* **Fix:** add visible labels and state the password rule outside the placeholder.

16. **[HIGH] a11y — admin config editor's validation errors aren't perceivable without scrolling and aren't tied to the field.** `respin/app/(admin)/admin/config/config-view.tsx:94-133` — the `role="alert"` error block renders above a 24-row textarea and the Save button the operator was scrolled to; nothing moves focus/scroll on error, and the issue list has no `id`/`aria-describedby` link to the textarea. WCAG 2.4.3 / 1.3.1. *Evidence: `accessibility-critic` finding 2.* **Fix:** move focus to the alert on error; link the textarea to the issue list via `aria-describedby`.

17. **[MEDIUM] a11y — billing page's disabled-control reasons are visible but not programmatically associated with their controls** (`billing-view.tsx:129-138,380-387`). WCAG 1.3.1/3.3.2. *Evidence: `accessibility-critic` finding 3.* **Fix:** `aria-describedby` from each disabled control to its reason text.

### Security & supply chain

18. **[CRITICAL] supply-chain — no dependency-vulnerability scanning exists anywhere for `respin/`** (no CI audit step, no dependabot/renovate, no audit script). *Evidence: `supply-chain-critic` finding 1.* **Fix:** wire `pnpm audit` (or equivalent) into CI.

19. **[CRITICAL] supply-chain — no LICENSE file anywhere in the repo for what `NORTH_STAR.md` calls "a subscription service."** *Evidence: `supply-chain-critic` finding 2.* **Fix:** add a LICENSE (or explicit proprietary notice) naming the actual posture — a checklist flag, not legal advice.

20. **[MEDIUM] security — auth rate limiting relies entirely on Better Auth's default, which is off outside `NODE_ENV=production` and untested.** `create-auth.ts:37-67` passes no `rateLimit` option; no test exercises it. *Evidence: `security-critic` finding 1.* **Fix:** set an explicit rate-limit config with durable storage and a test asserting it's active.

21. **[MEDIUM] architecture/security — `stripe_events.payload` stores complete, unredacted Stripe webhook JSON (customer email, name, address) indefinitely, with no retention policy independent of workspace deletion.** *Evidence: `architecture-critic` finding 2 + `security-critic` finding 2 `(cross-critic)`.* Not currently exploitable (nothing reads it outside the dispatcher today) but becomes one the moment a future surface does. **Fix:** name a retention window in `decisions.md`, or add redaction before any new surface reads this table.

### Architecture (shape, not yet a defect)

22. **[MEDIUM] architecture — the ledger fold is O(n) over a workspace's entire history under a full-workspace advisory lock, with a named-but-uninstrumented escape hatch.** `decisions.md` R-20/D-M1-7 says "revisit if fold cost bites" but there's no metric or threshold that would surface it before it does. This lock will also serialize concurrent generations on the same multi-seat Studio-tier workspace once M3 lands. *Evidence: `architecture-critic` finding 1.* **Fix:** add a per-workspace ledger-row-count/fold-duration metric now.

23. **[MEDIUM] architecture — no profile-level tenancy cage is designed yet for M2's `creator_profiles`,** despite R-9 ("nothing crosses profiles or workspaces") and a schema that nests profiles under workspaces. The existing `withWorkspace`/`VerifiedWorkspaceId` cage is workspace-grained only; its own comment already anticipates the gap. *Evidence: `architecture-critic` finding 3 + `respin-tenancy-reviewer` NOTE `(cross-critic)`.* **Fix:** extend the same brand-cage pattern to a `VerifiedProfileId` before M2 code lands.

## NORTH_STAR.md — does anything warrant a change?

**No structural revision is warranted.** A dedicated depth read verified every checkable claim in `NORTH_STAR.md` — the M1 gate verdicts, the E8/E9 evidence status, "no deploy surface exists yet," the four PRD §5 success numbers, the R-1/R-8/R-9/R-10 citations, and the "M2 is next, not started" claim — against the actual repo state, and all of them hold. The only defect found is cosmetic: `NORTH_STAR.md:10` cites "PRD §5.2" for the kill-test claim, but `docs/initial/PRD.md` §5 is a flat unnumbered list with no `§5.2` heading (item 30 above).

What this audit *does* suggest, though not as a NORTH_STAR edit: the durable order NORTH_STAR states (brain-as-context, honest evidence loop, compounding library) is a product-priority ranking that M1 correctly built billing ahead of, by design — that sequencing is not in tension with the doc. The gap this audit found isn't between NORTH_STAR and the code; it's between the code and its own already-correct spec (REQ-G08's pause invariant, items 1–2 above). Fixing the code, not revising the star, is what's called for.
