## Findings

- ⚠️ CHANGE `respin/packages/db/tests/system-spend.test.ts:225-236` — The "no creator/workspace/profile identity column in any retained system table" witness cannot fail for the realistic defect. `expect(cols).not.toEqual(expect.arrayContaining(["creatorId","workspaceId","profileId"]))` only goes red if **all three** columns are added at once; adding `workspaceId` alone to `system_spend_claims` stays green. The parent asked me to confirm this test would fail if a column were added: it would not. The private-claim case at `:613-614` covers `system_model_usage` only. Also, phase-card acceptance 12 ("delete tenant detail → totals remain") is marked `[x]` but no test deletes a profile and re-reads `system_spend_daily` (grep of `**/tests/**` for `systemSpendDaily` finds only this file, `import-boundary`, `table-writers`); the property currently rests on "no FK to a tenant row", which is a structural claim proven by argument, not by a run. · Fix: assert per column (`for (const c of ["creatorId","workspaceId","profileId"]) expect(cols).not.toContain(c)`) over all five system tables, and add one case that finalizes a private-claim attempt, deletes the profile, and asserts the usage row and daily totals survive.

- ⚠️ CHANGE `respin/packages/db/src/autopsy-policy.ts:8` + `respin/worker/autopsy-vendor.ts:156` — `AUTOPSY_CLAIM_LEASE_MS = 10 min` is a code literal while the per-stage vendor bound is config `llm.overallDeadlineMs` (`schema.ts:452`, positive int, no ceiling). Four sequential stages run under one lease, so an operator setting `overallDeadlineMs > ~150s` makes a healthy in-flight attempt's lease expire mid-pipeline; `recoverStaleSystemAutopsyAttempts` (`system-spend.ts:110-197`) then records four unknown calls, moves the cache to `failed`, and the next dispatch tick makes a second paid attempt while the first is still calling the vendor. That is exactly the case R-93 rules out ("no stale lease authorizes a second paid call merely because time passed"). Not reachable at seed defaults (4 × 40s = 160s < 600s), which is why this is CHANGE, not BLOCK. Confidence: high on mechanism, medium on reachability. · Fix: derive the lease from the deadline (`lease ≥ AUTOPSY_VENDOR_CALLS_PER_ATTEMPT × overallDeadlineMs + margin`) or refuse at `activeSystemConfig` when the config deadline × 4 exceeds the lease, and pin it with a test.

- ⚠️ CHANGE `respin/packages/credits/src/mode-access.ts:166-174` — `TIER_TRACKED_NICHES = {free:0, creator:1, pro:3, studio:10}` is a numeric per-tier allowance in code (B5). This file's own header (`:4-8`) argues that the profile cap, concurrency limit and monthly allowance "are NUMBERS in config" and that only *sets* (modes) belong here; `profileCaps` was moved to config for the same PRD §4G table row shape (`schema.ts:101-123`). The numbers do match REQ-E05 / PRD §4G "Trend monitor" row exactly (B6 holds), and `mode-access.test.ts:281-305` pins totality and the cast-in-tier refusal, so this is placement, not correctness. · Fix: add `trackedNiches: z.object({free,creator,pro,studio}).default({0,1,3,10})` beside `profileCaps`, read it through `getWorkspaceBillingState`'s document, keep the totality test.

- ⚠️ CHANGE (check 7) three uncited literals that shape money — `respin/worker/production.ts:37` `SYSTEM_AUTOPSY_INPUT_TOKEN_CODE_CEILING = 100_000` (this number, times the Haiku price, **is** the per-attempt reservation: 100k×1000 + 16k×5000 nano = 180,000 micro-USD); `respin/packages/db/src/system-spend.ts:53` `SYSTEM_AUTOPSY_DISPATCH_BATCH_CODE_CEILING = 32`; `autopsy-policy.ts:8` the lease. None cites PRD §4G, a decision, or a measurement. The $100 ceiling (R-89) and the five-attempt ceiling (R-93) are properly cited by contrast. · Fix: cite each (decision or "unmeasured launch bound, revisit trigger: N observed autopsies") in the same edit, or move the input ceiling to config with a `.default`.

- 💡 NOTE `respin/packages/db/src/system-spend.ts:229-231` — `budgetSpentMicroUsd` is `reservedMicroUsd`, and reservations are never released on success (deliberate, `:102-108`). So the $100/day cap is a *reservation* cap: at seed prices it admits ~555 autopsies/day whatever the measured spend (~$0.01–0.02 each). Safe direction, but the health field, the `budget_exhausted` alert and runbook §"budget" call it "spent". The 10b-1 margin view must read `known_cost + unknown share`, never `reserved`. · Rename to `budgetReservedMicroUsd` and say "reservation cap" in the runbook.

- 💡 NOTE `respin/worker/production.ts:98-102` — the pre-dispatch check compares reserved spend to the **config** cap, not the retained daily cap (`operational.budgetCapMicroUsd`). On a day whose retained cap was clamped below config (`system-spend.ts:332-340`, tested at `system-spend.test.ts:322-338`), every tick dispatches up to 32 candidates that each write a durable `cap_exhausted` claim + `budget_exhausted` usage row. Zero vendor calls, zero money, but unbounded row growth. · Compare against `operational.budgetCapMicroUsd` when it is non-zero.

- 💡 NOTE `respin/worker/production.ts:145` — `"respin-system-worker"` literal vs `input.runtime.workerName` at `:198`; affects only the health fields of the operational read, not the budget (keyed by date).

- 💡 NOTE `respin/packages/db/src/seed.ts:51` / PRD §4G:137 — `creditCosts.autopsy = 4` has no reader anywhere (`priceOf` has no branch for it; `UNPROBED_CREDIT_COST_KEYS` says so). Under R-89 all autopsies, including profile-private ones prepared by `claimPrivateAutopsyForSystem` (`trends-storage.ts:415-470`), draw the shared system budget at zero credits, with no per-profile bound on private claims. **Not reachable today**: `trends/actions.ts` has no submit action, so no creator can mint a private claim. When REQ-E07 lands, "does a creator-submitted autopsy debit `creditCosts.autopsy` or draw the shared $100" is a decision neither R-89 nor R-90 makes, and without it one Free creator could starve the product's daily budget for everyone. · Record on the slice-10 card as a decision the submit slice must make before it ships.

- 💡 NOTE `respin/packages/db/src/trends-storage.ts:655` — `spinReferenceForProfile` throws a bare `Error` on an inaccessible/unready autopsy id. Money-safe (it runs at step 5, before balance, slot, claim and vendor), but no test drives a foreign or incomplete id through `generate` to witness "zero vendor calls, zero debit". Tenancy gate's call on the cross-profile half; here it is a missing money witness.
