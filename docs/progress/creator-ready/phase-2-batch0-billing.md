## Least-confident probe (author's line) — HELD, by code reading only

`buildVoiceBrain`'s busy→empty→terminal discrimination (`brain.ts:342-352`) is sound against the product as built: `run-status` is ALWAYS in the DOM and empty when idle (`run-inference-panel.tsx:107-115`, text only while `isPending`), `RunOutcome` renders from the `useActionState` value so the first press's `run-refusal` banner is replaced in the same commit that clears `isPending` (`run-inference-panel.tsx:82-84,161-165`; `run-outcome.tsx:42-72`), and the terminal node is read only after `toHaveText("")` passes. So on a real retry the node read is press 2's, not press 1's stale banner. Two residuals, both loud rather than silent: (a) a pre-vendor refusal whose round-trip is shorter than one animation frame could be missed by the busy-first `waitFor` at `:346`, which then times out after 15 s and throws — the press-2 record stays `unknown` (fail-closed), the journey fails; (b) nothing exercises this at runtime — it is Playwright-only code with no unit harness, and no real `run_slot_busy` has ever been produced by the journey. I did not run a browser.

## Findings

- ⚠️ CHANGE (Medium) `respin/e2e/support/brain.ts:377-384` — The retry decision is code-only: `preVendor && pressOrdinal === 1` re-presses regardless of the press's own `consumed` classification. If the before/after snapshot read fails (`:326-330`, `:364-368` swallow the error into a note and leave `before`/`after` null), the record is `unknown` **and the journey still presses again**. The contract (plan §Handoff Contracts, line 74) says unknown "never … authorize[s] another dispatch" and "never infer from code/kind"; a second press on unknown evidence is a second potential metered call whose first press's claim state is unestablished. Per product code the two retry codes are thrown at `inference.ts:771` before the vendor call and before `recordUsage`/the claim, so today a *correctly classified* retry is safe — the gap is the blind path. · Fix: gate the `continue` on `consumed === false` as well (`if (preVendor && pressOrdinal === 1 && consumed === false)`); on `unknown` record and return `refused` without re-pressing, and note why.
- ⚠️ CHANGE (Medium) `respin/e2e/support/brain.ts:257-258` and `respin/tests/journey-voice-evidence.test.ts:63-67` — Classifier deviation pinned by a fixture: a NEW claim whose only same-scope usage row has `consumed_included_build = false` returns `{attemptId, consumed: false}`; the contract says "conflicting claim/usage → unknown". The product writes a claim **iff** the returned usage row is billable AND `consumedIncludedBuild` (`with-workspace.ts:4058-4070`), so "new claim + no consuming row" is a writer conflict, not a truncation (a truncation writes usage and no claim — `inference.ts:951`, `with-workspace.ts:4050-4052`; that case is the test's second assertion at `:68-71` and is correct). The fixture's first assertion (`snap([A],[row(A,false,"schema_invalid")]) → false`) encodes the liberal answer for an impossible state — it would under-count a consuming refusal and let a dispatch proceed. · Fix: in `classifyPress`, when `newClaims.length === 1` and no new usage row for that claim is `consumed`, return `unknown`; change the fixture at `:64-67` to expect `"unknown"` and keep `:68-71` as the truncation → false case.
- 💡 NOTE (Low) `respin/e2e/journeys/editor-seat.spec.ts:154-159` (pre-existing, touched chapter) — If a live `pause-form` ever rendered for an editor (`billing-view.tsx:608-611` renders it only for owners with a live subscription), the failed `toBeDisabled` is swallowed by `.catch` into a plain note — a role-boundary breach on a money control recorded as non-BLOCKING. · Fix: `await expect(page.getByTestId("pause-form")).toHaveCount(0)` for the editor (settled, unconditional).
- 💡 NOTE (Low) `respin/e2e/support/artifacts.ts:146-152,162-169` — `currentRunId()` falls back to the literal `"local"` and `clearConsumptionRecords` clears only the running persona's files; a partial local run (one persona) validated with `--run-id local` would count a stale sibling persona's `"local"` record from an earlier run as this run's. CI is unaffected (unique `<run>-<attempt>`, fresh checkout). · Fix: refuse `"local"` in the validator unless `--run-id` is passed explicitly, or fail `currentRunId()` when neither env var is set.
