  **Three things building surfaced that six rounds of plan review could not.**

  1. **drizzle-kit 0.31.10 cannot serialize a BigInt default.** `.default(0n)` typechecks and then throws `TypeError: Do not know how to serialize a BigInt` inside `db:generate`. A bigint default must be written as `sql\`0\``.

  2. **A composite FK cannot reference a `uniqueIndex` in a drizzle-generated migration** — an ordering trap, not a syntax one. drizzle-kit emits every `CREATE TABLE`, then every FK `ALTER TABLE`, then every `CREATE INDEX`, so the index does not exist when the FK is added: `there is no unique constraint matching given keys for referenced table "creator_profiles"`. The fix is a table-level `unique()` **constraint**, which is emitted inline in `CREATE TABLE`. **The plan's own migration step said to inspect the emitted SQL for four things Drizzle may not produce — the constraint was PRESENT and the check passed; it was present too LATE.** "Verify it is emitted" and "verify it is emitted in a working order" are different checks.

It reports correctly when there is nothing pending, so the failure is invisible exactly when something is wrong. The real error came out immediately from `drizzle-orm`'s own programmatic `migrate()`.
