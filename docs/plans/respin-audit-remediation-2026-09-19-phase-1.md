# Phase 1 — Open gates and the live disclosure breach

Depends on: none. Owner: `respin-engineer`. Est. 3–4 h.
**Read first:** [`../progress/respin-audit-remediation-2026-09-19-codebase-review.md`](../progress/respin-audit-remediation-2026-09-19-codebase-review.md) §2 and §3, and the master plan's *Pinned conventions*.

## Objective

Close the one live breach of an owner-approved decision, and shut the instruments that currently report PASS while matching nothing. Everything here is small and independent; what makes it first is that later phases prove their own work with these scanners, and a scanner that cannot fail is worse than no scanner — it makes an absence look like a control.

The phase's organising move is rule 7: three of the six requirements are answered by **one** shared, on-disk-asserted population rather than by six list edits — and the population of *tests that carry their own root list* is itself censused, so the shared module cannot be bypassed by a sixth private copy.

**Lessons that bite here** (verbatim, master plan): the 2026-08-26 planted-violation lesson; the 2026-08-18 generative-against-the-installed-parser lesson; the 2026-09-18 line-endings lesson.

The rule-7 fix the codebase review §1 names: every `customRules` key is asserted against the **installed** route set (`Object.values(auth.api).map(e => e.path)` — `better-auth` exports `getEndpoints`, every endpoint carries `.path`), the key is renamed, `/send-verification-email` gains a rule, and the comment at `:384-387` stops naming `tests/auth.test.ts` (which does not exist at that path — the rate-limit test is `packages/auth/tests/rate-limit.test.ts`).
  **The ∈-set assertion is necessary, not sufficient (tenancy CHANGE, batch 0).** The installed matcher is `p.includes("*") ? wildcardMatch(p)(path) : p === path` (`respin/node_modules/better-auth/dist/api/rate-limiter/index.mjs:302-304`), so a parameterised route such as `/reset-password/:token` can only be covered by a **wildcard** key — which a plain ∈-set assertion would reject — while a literal `/reset-password/:token` key passes the set test and never matches a request. So the assertion admits a key containing `*` when `wildcardMatch(key)` matches at least one installed path, admits an exact key when it is an installed path, and **refuses** any key containing `:` (a route-parameter literal). And because a key in the set proves configuration, not behaviour, AC9 drives **one handler-driven 429 per key** in the `rate-limit.test.ts:44-83` shape (a real `Request` through `auth.handler` with a fixed `x-forwarded-for`).
