# Scope note — Respin M2b-2: the metered inference path

**This is a scope contract, not a plan.** It is written now so that nothing from the M2b round-1 gate is lost, and it will be **planned as its own document once [`respin-m2b1-brain-surface-plan.md`](respin-m2b1-brain-surface-plan.md) is Ready** — following the M2 master plan's own doctrine: re-plan one small document at a time, once the substrate exists.

**Do not implement from this file.** It carries findings and constraints; it has no tasks, no acceptance criteria and no mutation matrix, and it has not been gated.

**Depends on:** M2b-1 (the brain-document surface). **Blocks:** M2c.
**Origin:** the second half of [`respin-m2b-plan.md`](respin-m2b-plan.md), which took BLOCK from all four Critical-Path reviewers on 2026-08-24 ([`../progress/respin-m2b-plan-review.md`](../progress/respin-m2b-plan-review.md)).

## Why this half goes second

The round-1 draft ordered it first. That was wrong, and the reason is the failure mode that produced the split: `runInference`'s pause gate, its debit, and its metering authority only become *real* when the operation has a consumer that actually persists something. M2b-1 builds that consumer — a gated, capability-bounded brain-document write surface. Landing the metering path against it means the gate is exercised rather than asserted, instead of repeating M2a's mint, which held trivially because nothing called it.

## Scope

`packages/llm` (the Anthropic adapter), `runInference` (the metered operation), `createProfile` and the profile lifecycle, the config keys, the spend rollup and reconciliation, and the product's **first credit debit**.

## Blocking findings inherited from the round-1 gate — each must be closed by the plan

**Billing (`respin-billing-reviewer`)**

1. **The model must not be called before the workspace is known to be able to pay, and a debit refusal must not destroy the spend record.** Round 1 put the adapter call before a transaction holding `model_usage` + rollup + debit; `debitCredits` refuses *after* the tokens are spent — on `InsufficientCreditsError` (`ledger.ts:347`), a pause opened mid-flight (`:343`), or `assertWriteClock` (`:341`) — and each throw rolls back the transaction the usage row was in. Read the balance and refuse **before** the call; write `model_usage` in its own committed transaction (A-7's settlement-tail exemption) and compose the debit after. **The pre-call check composes `maybeAutoTopup` before deciding, but a TRIGGERED top-up does NOT license proceeding to the model call.** Measured for round 4: `packages/credits/src/stripe/auto-topup.ts:215-217` records that credits land via the `payment_intent.succeeded` webhook — “**never here**” — and `maybeAutoTopup` returns `{triggered, paymentIntentId}` without moving the balance. So auto-top-up settles **asynchronously**, and the round-3 wording (“composes `maybeAutoTopup` BEFORE refusing”) licensed calling the model on a triggered-but-unsettled top-up: **tokens spent, `model_usage` committed, debit still refuses — an unmetered generation, on the product's first debit.** The correct shape: attempt the top-up, then **refuse THIS attempt regardless**, and let the refusal say that **the top-up is settling — retry once it lands**. It must NOT promise the next attempt will succeed: an off-session `confirm: true` PaymentIntent can decline, the webhook can lag, and the monthly cap can bite on the next trigger, so a refusal that guarantees success is a support incident on the product's first debit (non-negotiable 6). **The pre-call check must also catch every top-up outcome — returned OR thrown** (`auto-topup.ts:123-125` throws deliberately when `mayChargeOffSession` refuses for an unnameable reason, and a declined off-session PI raises from `paymentIntents.create`) and always emit the credits refusal with its top-up prompt, never an unmapped error. The customer who consented to pay is not abandoned: the charge is attempted, and once it settles the balance carries it. That is the point of deriving the balance from the **ledger** rather than from an **intent** — an intent is not money, so nothing downstream may treat one as though it were. *(Round 2: the first draft of this note dropped auto-top-up entirely. Round 3: restoring it reintroduced the unmetered-generation window one line down — the recurring shape where fixing a named finding opens the class one level lower.)*
2. **The one free included build must not be a check-then-act race.** `COUNT(DISTINCT attempt_id) < 1` in application code, with the zero-cost path skipping `debitCredits` **and therefore `takeWorkspaceLock`**, lets two concurrent calls both run free. Settle it in the schema or take the workspace lock at operation entry regardless of cost, and prove it with a two-connection Docker case.
3. **An archived profile must not be able to generate.** `assertProfileCap` is a workspace-level count of *active* profiles, so archiving down to the cap and then generating against an archived profile passes it. `ProfileScope` carries no `state`.
4. **The `.default()` deploy window must not mis-attribute money.** `getActiveConfig` returns the *stored* row's version with *defaulted* content (`config/src/index.ts:41`), so between deploy and `migrate-config` a debit is stamped with a `config_version` whose document lacks the keys that priced it. Fail closed on the **raw stored** document's missing keys rather than spending.

**Tenancy (`respin-tenancy-reviewer`)**

5. **`createProfile` must call `assertScoped`.** Reading `scope.role === "owner"` without it accepts `Object.assign({}, viewerScope, {role:"owner"})` — the A-3 escalation — and a forged `workspaceId` creates a profile in another workspace. *(M2b-1 task 19 extends the completeness scan's roots to every `packages/*/src`, so this becomes visible; M2b-2 must satisfy it.)*
6. **`runInference` must have a role gate.** REQ-A02 is explicit that a viewer may not generate; round 1 shipped the first generation operation and its `app-server` surface with no role check, deferring roles to M6 in wording that would read to M2c as "handled".

**Learning / compliance**

7. **`model_usage.resolved_tier` and `cost_state` must be inexpressible by the caller** (R-30 constraint 8) — and the mutation must cover the **runtime** half, not only the typed half. Build the `recordModelUsage` argument field by field; never spread caller params.
8. **The outbound-egress boundary must be constrained, not just the test tree.** M2b-2 lands the repo's first HTTP client in `packages/**`. Assert that the only reachable outbound host from product code is the configured Anthropic base, proved by a planted `fetch` to a closed platform, and that `baseURL` is not overridable from product code.
9. **No prompt or completion text in logs or thrown error messages.** `assertMeteringOnly` structurally covers `usage_raw` only.

## Design corrections carried forward

- **Price in nano-USD per token, not micro-USD.** "Whole dollars per MTok, so micro-USD per token is integral" is false in general: sub-dollar-per-MTok models and cache-read/write multipliers are fractional (a $5/MTok input at 0.1× cache-read is 0.5 micro-USD/token). DL-12 defers caching to M3, so the unit breaks one milestone out — on an append-only versioned document whose historical rows would silently change meaning. `cost_micro_usd` stays the stored unit, and the conversion **rounds UP (ceiling), never truncating**, with a test at a sub-micro-USD price. *(Round 2 caught the first draft of this correction reintroducing its own defect one line later: "divide at the end in `bigint`" truncates, which understates cost and therefore **overstates margin** — the direction `tech-spec.md:68` names as the dangerous one for the number R-6 tunes pricing against. A carried finding must not smuggle back the failure it was carrying.)*
- **Classify the whole `model_usage_outcome` enum.** It has five values (`succeeded`, `schema_invalid`, `rate_limited`, `unavailable`, `refused`); round 1 classified two or three, left `refused` unclassified, and had no distinct value for a pre-response transport failure. Assert exhaustiveness over `usageOutcome.enumValues`.
- **A `schema_invalid` response must not consume the one free attempt without a bounded retry.** That is *our* prompt failing. Free has no minting until M3, the rebuild is priced, and `profileCaps.free = 1` blocks the new-profile workaround — so a Free workspace whose single build returns invalid schema would be locked out of ever having a brain. `model_usage`'s own comment anticipates the fix ("a bounded retry writes two rows"); the retry must share the **same** `attempt_id`.
- **`reconcileWorkspaceSpend` must be well-defined**: per-`tier` (the rollup grain is `(workspace_id, period_month, tier)`); a repair path for the sanctioned `estimated → reconciled` update; an explicit rule for `cost_state='unknown'` rows whose cost is NULL (a naive `sum()` treats absent as zero — understating cost, **overstating margin**, on the one aggregate that survives deletion); and a distinct status after a REQ-A04 deletion rather than maximal false drift. Give the rollup an excluded-count column so REQ-G05's excluded share survives deletion.
- **Name the adapter injection seam.** "Provable by handing `runInference` a stub that throws if invoked" requires the adapter to be a **parameter**, not a module import stubbed with `vi.mock`. This is the decision the whole pause-gate argument rests on. Add a vitest setup-level outbound interceptor alongside the source scan.
- **Name the clock.** `DebitParams` requires `at: Date`, bounded by `assertWriteClock`; the repo's discipline is `getDbNow(tx)`, never `new Date()`.
- **`migrate-config` migrates TOP-LEVEL keys only** (`migrate-config.ts:107,116`), so `creditCosts.onboardingBrainRebuild` would land only as a side effect of `appendConfigVersion` re-parsing. Assert the **stored** document after migration, and either teach the migrator to recurse or record the limitation.
- **`createProfile`'s cap is a SELECT-then-INSERT race** with no lock — the same defect as finding 2, on the entitlement counter. **`activateProfile` has no cap check**: archive → reactivate is an unbounded route back over the cap.
- **Strike "REQ-G05 already excludes `unknown`"** — `tech-spec.md` §2 says the opposite in terms ("no aggregation code and no test, the margin dashboard is M6").
- **Read the tier once per operation** and reuse it; round 1 read `getWorkspaceBillingState` twice per `runInference`, so the cap check and the `resolved_tier` stamp could disagree.
- **`profileCaps` is editable from `/admin/config`**: lowering it disables generation for every over-cap workspace with no downgrade involved. B-13 reasoned only about Stripe-driven downgrades.
- New errors (`ProfileCapExceededError`, `ModelPriceUnavailableError`) need app-facing copy or they render "Something went wrong".

## Owner decision still open

**`creditCosts.onboardingBrainRebuild` has no doc authority.** D-M2-2 creates the key and leaves the value open; the round-1 draft proposed **5**, anchored to `fullScript`/`spin`. The billing reviewer accepted the flagging but not shipping the flagged value: it prices the **first credit debit the product ever takes**, it is append-only history on a live ledger, and 5 credits is unpayable by exactly the Free creator most likely to need a rebuild. **Owner confirmation is a precondition of the config data step**, not of M2c's UI.

## Testing discipline the plan must carry (recovered after round 2)

- **Every money-path AC ships a discriminating mutation.** Round 1's draft left AC-6, AC-7 and AC-11 — attempt counting and the fail-closed price lookup, the three guarding the first real spend — with no mutation at all, and gave AC-1 and AC-13's source scans no planted violation. The test of a mutation is not that it reddens *something*: it is that the **vacuous** implementation would also fail it.
- **The pause fixture must discriminate the authority from the mirror.** `runInference`'s pause test uses an open `pause_periods` row with **no `subscriptions` row**, so `hasOpenPause` is true while `isPausedSubscription` is false — plus M2a's harder `{open pause, mirror canceled}` shape. Without it the test passes against an implementation reading the non-authority, and every M2 onboarding workspace has no subscription row.
- **Any post-call persist refusal is a money event.** M2b-1 adds roughly **seven** new ways a model-produced brain document is refused *after the tokens are spent*: content-schema failure, `KindNotYetWritableError` for `performance_meta`, the non-empty `source_evidence` CHECK, a dangling field pointer, the 8-segment echo bar, the 240-character quote cap, and the walker's fail-closed refusal. The `schema_invalid` lockout argument generalises to **all** of them: each must (i) leave the separately-committed `model_usage` row intact, (ii) map to a named value of `usageOutcome.enumValues` with exhaustiveness asserted — note a kind refusal is schema-*valid*, so the five current values do not cover them — and (iii) not consume the one free included build without the bounded retry under the same `attempt_id`. Otherwise a Free creator whose single build echoes one sentence is permanently brainless.

## Constraints inherited from M2b-1

- `performance_meta` is not writable (M2b-1 C-12) — the inference path must not write it.
- The pause gate at operation entry, before the model call, remains R-30 constraint 1, load-bearing because a zero-cost operation skips `debitCredits` entirely (`ledger.ts:339`, verified).
- One debit per `attempt_id`, settled by a partial unique index on `(ref_type, ref_id) WHERE ref_type = 'inference_attempt'` — shape verified against the three existing precedents, and `ref_type` is `text`, so no `ALTER TYPE` is needed.
- `workspace_spend_monthly` pseudonymisation stays re-taken in writing (DL-11) with the constraint binding M6; its first writer lands here, so the registry entry must be updated in the same change.
- **`creator_profiles.state` is NOT carried on the scope.** M2b-1 lands the column with no writer and deliberately keeps it off `ProfileScope`: a scope-carried `state` is a snapshot that goes stale across an archive, so finding 3's refusal must read the row at operation time. Recorded here so M2b-2 does not discover it as a surprise while widening the mint.
- **`ProfileScope` already carries `role` and `userId`** after M2b-1 C-12/C-13, so finding 6's role gate on `runInference` has its authority available at mint and does not need a new seam.
- **Amend `tech-spec.md` §2 by bullet, never wholesale.** §2 holds the `brain_docs` bullet *and* the `model_usage` / `workspace_spend_monthly` bullets — including the REQ-G05 "never `unknown`, reports the excluded share" sentence and the R-30-constraint-8 sentence, both of which this note relies on. Scope every edit and assert the neighbours byte-unchanged.
