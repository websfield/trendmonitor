### The rule this revision is written to

Four rounds produced one pattern with no exception: **a finding is closed at the instance it names and the class reopens one level down.** Round 4 produced it inside modules built expressly to end it. The diagnosis round 4 reached is precise, and this revision adopts it as a rule:

> **An acceptance criterion written against the implementation that exists cannot detect a violation of the property being claimed. Every criterion below names the PROPERTY, and every mutation must be a plausible WRONG IMPLEMENTATION of that property — not a deletion of the current code.**

The test: *if I wrote this feature from scratch and got the property wrong, would this criterion fail?* Round 4 proved the previous answer was "no" for at least four criteria — `P-2` (a payload-walking enumerator is byte-identical on every fixture), `AC-45` (the smuggle it describes cannot occur), `AC-9`/`P-7b` (the probe is lazy and nothing stubs it), `AC-1`/`P-3` (no registered kind has a nested node, so the depth case has no site). Each is fixed below by adding the fixture that **discriminates**, not by rewording.

Three corollaries this revision applies throughout:

1. **A marker with nothing enforcing that it is applied is not a guarantee** (ROOT A). `claim()` was "by construction"; nothing checked the construction.
2. **A guard that runs only in a test is a test, not a guard** (`assertClosedSchema` had no production caller).
3. **An enumerated list of counterexamples is not a class** (`ZERO_WIDTH` missed U+00AD, which a PDF paste inserts routinely) — the 2026-08-18 lesson, in the module written to honour it.
