## Edge Cases & Failure Paths

- **Inverse events:** sign-out revokes the session (Better Auth); account deletion still M6 (unchanged ledger row). Auth tables join the future export/deletion surface — noted on the M0 ledger row, receiver unchanged.
- **Double failure:** session exists but domain bootstrap fails (DB down) → error boundary, no partial rows (transaction, unchanged tests).
- **Degraded:** cookie present but session revoked/expired → middleware lets the request through (optimistic), the server gate refuses → redirect to `/sign-in`; test the server-refusal path. Missing `BETTER_AUTH_SECRET` → named error at call time, not import time.

## Failure Modes & Degraded Behavior

| Boundary | Failure | Degraded behavior | Proof |
|---|---|---|---|
| Middleware (optimistic) | forged/stale cookie | request passes middleware, server gate refuses (this is by design — middleware is UX, not the gate) | server-gate test |
| Better Auth API route | malformed request | library's own 4xx; no domain writes | smoke via real sign-up test |
| Google provider unconfigured | social sign-in attempted | button not rendered (flag); direct API call fails with library error, no crash | flag test |
| Password reset in production (no email provider yet) | reset requested | URL (a bearer credential) never enters logs outside development — event-only log line | stub guard test |
| Admin env unset | any admin request | `requireAdmin` throws/notFound — denies everyone | fail-closed tests (layout + page) |

## Handoff Contracts

- To M1: `getSessionUser()` is the sole way app code learns "who is calling"; `requireAdmin()` is the admin pattern every M6 page must call. The env inventory above is the deploy contract.
