# Cutdown — Phase 0 Decision Record

**Purpose:** every decision the PRD (§18) and tech-spec (§16) left open, plus every implicit hedge found in review, resolved for Phase 0 so an unsupervised developer is never blocked or guessing. Each entry is one of:

- **DECIDED** — a concrete default. Build against it. The *revisit trigger* says when it gets re-examined; until then it is settled, not a suggestion.
- **OWNER** — genuinely the owner's call (money, licenses, client data, external naming). The *escalation trigger* says exactly when to stop and ask; until that trigger fires, the stated interim behaviour applies.
- **OPEN (Phase 1+)** — deliberately left open because nothing in the Phase 0 build sequence depends on it.

New decisions made during the build are **appended here** by the developer per the escalation protocol in `developer-guide.md` — this file is the shared memory that replaces owner oversight.

| D-40 | 2026-07-21 | REQ-001 names six asset classes but no rule assigns a file to one. How does `ingest` classify, and how are `image` and `logo` — which share every raster extension — told apart? | **Extension-first, with an explicit declaration always winning.** (1) If a rights sidecar declares `assetKind`, that is authoritative — inference never overrides a human statement. (2) Otherwise classify by extension: `video` = mp4/mov/mkv/webm/avi/m4v; `audio` = m4a/wav/mp3/aac/flac/ogg; `subtitle` = srt/vtt/ass/ssa; `brand_reference` = md/pdf/docx/txt/rtf; raster = png/jpg/jpeg/webp/gif/bmp/tiff. (3) A raster splits `logo` vs `image` on **a real alpha channel** — an alpha-capable pixel format AND at least one non-opaque pixel. A logo without transparency, or a photo saved with alpha, is therefore misclassified — which is exactly why rule (1) exists as the escape hatch, and why misclassification is a warning naming the relative path, never a silent assumption. Anything unmatched fails the whole atomic ingest naming its relative path (REQ-001). | A client corpus where alpha-based logo detection is wrong more than occasionally, or the arrival of a real brand-reference format (Figma export, InDesign) that needs media probing rather than an extension test. |
| D-41 | 2026-07-21 | Rotation metadata: `-metadata:s:v rotate=90` is silently dropped by FFmpeg 8, so which field does preflight actually read? | **Read the Display Matrix side data (`stream_side_data_list[].rotation`), not `stream_tags.rotate`.** Verified empirically while building the `ugly.mp4` fixture: FFmpeg 8 ignores the `rotate` output tag entirely, and the working producer route is `-display_rotation:v:0 90` as an *input* option on a `-c copy` remux. Preflight reads side data first and falls back to the legacy tag only for older files that still carry it, normalising both to `rotationDegrees` ∈ {0, 90, 180, 270}. Display dimensions are then derived from coded dimensions plus this value — editorial code reads display dimensions only, so a rotated phone clip cannot produce a sideways crop. | A source whose rotation is expressed some third way (container-level, or a non-90° matrix). |

| D-42 | 2026-07-21 | D-25 specifies the proxy recipe as "720p-fit H.264 CRF 23 + AAC 128 kbps, constant frame rate". Which asset kinds get a proxy? An audio-only asset has no video stream, so the recipe cannot be applied to it. | **Video only.** D-25's recipe is a video recipe and is undefined for an asset with no video stream — the renderer refuses it outright. Audio, image, logo, subtitle, and brand-reference assets carry `proxy: null`, which the schema already distinguishes from "a proxy was expected and is missing".
