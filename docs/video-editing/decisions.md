# Cutdown — Phase 0 Decision Record

**Purpose:** every decision the PRD (§18) and tech-spec (§16) left open, plus every implicit hedge found in review, resolved for Phase 0 so an unsupervised developer is never blocked or guessing. Each entry is one of:

- **DECIDED** — a concrete default. Build against it. The *revisit trigger* says when it gets re-examined; until then it is settled, not a suggestion.
- **OWNER** — genuinely the owner's call (money, licenses, client data, external naming). The *escalation trigger* says exactly when to stop and ask; until that trigger fires, the stated interim behaviour applies.
- **OPEN (Phase 1+)** — deliberately left open because nothing in the Phase 0 build sequence depends on it.

New decisions made during the build are **appended here** by the developer per the escalation protocol in `developer-guide.md` — this file is the shared memory that replaces owner oversight.

| D-48 | 2026-07-29 | tech-spec §12.1 ships `caption <= 2 lines x 42 chars` as a QA threshold. But on the Phase 0 canvas (720x1280, 9:16) with a 3.8%-of-height caption font and the TikTok safe-area margins, 42 characters is roughly 1045 px of glyphs inside 460 px of usable width — not tight, impossible.
