# Audit Register — UGC Intelligence — 2026-07-14

**First audit of this repository.** Build state at audit time: all 10 phases (0-9) of the master plan complete per `docs/progress/ugc-intelligence/ledger.md` (through 2026-07-13) — C# control plane 395 tests green, Python intelligence plane 243 tests green, React frontend typecheck green with vitest never executed (environment-blocked, see `docs/progress/ugc-intelligence/phase-9-evidence.md`). Not a git repository.

**Overall readiness: Not yet — grade D.** One confirmed, reachable-today defect (#1) breaches the project's own non-negotiable rule 2 ("no auto-approval, ever"). Two further confirmed defects (#2, #3) mean the cross-process backbone the whole design depends on (C1 Python ↔ C2/C3/C4 C#) does not yet function even though every individual component's unit tests are green. Everything below the fold is real but not blocking in the same way.

## Ranked register

### `[CRITICAL]` 1. veto-verdict-integrity — Verdict override path can record APPROVED with no human-click timestamp and no live-veto re-check, and is already reachable from the built UI
- **Evidence:** `src/ControlPlane/UgcIntelligence.C2.Api/Verdicts/OverrideService.cs:21-39` takes a bare `originalVerdict`→`overrideVerdict` transition with only `reason`/`reviewerId` validated (lines 31-34) — no `ComplianceResult` parameter, so it cannot consult live veto state. `src/ControlPlane/UgcIntelligence.C2.Api/Events/ComplianceEventEmitter.cs:41-48` (`VerdictOverriddenRecord`) carries no `human_approved_at`-equivalent field at all, and `:165-187` (`EmitVerdictOverriddenAsync`) performs zero validation before appending — contrast `:134-138` (`EmitVerdictIssuedAsync`), which throws `AutoApprovalRejectedException` when `Verdict.APPROVED` has a null `HumanApprovedAt`. `src/Frontend/src/verdict/VerdictPanel.tsx:14` already lists `'APPROVED'` in `OVERRIDE_TARGETS`, and the override form (`VerdictPanel.tsx:156-195`) lets a reviewer pick it with any non-empty free-text reason — so this is a live, clickable path once a backend host exists, not dead code. Confirmed independently four times: the correctness critic, the audit chair's own direct read, a dedicated depth-room interrogation of `OverrideService.cs`, and the second-pass compliance sweep.
- **Fix:** Add a `HumanApprovedAt`/reviewer-click-timestamp field to `VerdictOverriddenRecord`, and in `EmitVerdictOverriddenAsync` throw the same `AutoApprovalRejectedException` guard whenever `OverrideVerdict == Verdict.APPROVED` and it's null. Additionally require the override path to accept and re-check a live `ComplianceResult` before allowing an override into `APPROVED`, so a fired/unevaluable veto can't be overridden away without a recorded, audited re-check.
- **Owner:** control-plane-engineer
- **ADR:** none required (implementation gap against an already-stated invariant, not a new decision) — but `veto-verdict-integrity` skill/reviewer should gain a permanent check for "every code path that can produce `Verdict.APPROVED`" the next time it runs, not just the issue path.

### `[CRITICAL]` 2. component-boundaries — the one Contract-B wire-format code path violates the schema it's supposed to satisfy, and the contract itself never states the requirement
- **Evidence:** `src/ControlPlane/UgcIntelligence.Events/AppendOnlyEventLog.cs:71` (`ToReplayExportNdjson`) calls bare `JsonSerializer.Serialize(e)` — no `JsonSerializerOptions` — against `OutcomeEvent` (`OutcomeEvent.cs:26-33`, PascalCase properties, undecorated int enum). `docs/initial/schemas/events-v1.json:20-33` requires snake_case keys and a string `event_type`. The rest of the codebase already knows the fix: `Mechanism.cs:98-103` and `ExemplarIndex.cs:25-29` both apply `JsonNamingPolicy.SnakeCaseLower` + a snake_case `JsonStringEnumConverter` for exactly this reason — `ToReplayExportNdjson` is the one Contract-B serializer that skips it. Python's `c1_pattern_engine/corpora/internal.py:66-79` expects plain snake_case keys and would fail to parse this NDJSON as written. `tests/Architecture/ArtefactAndEventLogTests.cs:239-251` only checks tenant scoping and a substring — nothing in the 395-test green suite catches this. A dedicated depth-room read of `docs/initial/integration-contract.md` (all 432 lines) independently confirmed the root cause is partly a **spec gap**: Contract B's section (`integration-contract.md:116-148`) never states a wire-format/serialization convention at all, unlike Contract A and Contract E, which both ship a worked JSON example. Confirmed independently four times: both architecture-critic runs, the correctness critic (cross-reference while reading the same file), and the integration-contract.md depth read.
- **Fix:** Apply the same `JsonSerializerOptions` used in `Mechanism.cs`/`ExemplarIndex.cs` to `ToReplayExportNdjson`; add a round-trip test that feeds the C#-serialized output into (a stub of) the Python `internal.py` assembler. Add one line to Contract B in `integration-contract.md` stating the required naming policy explicitly.
- **Owner:** control-plane-engineer
- **ADR:** revise `integration-contract.md` Contract B (not a full ADR) to name the wire-format requirement explicitly, since this is exactly the class of drift Phase 8's forbidden-verb lexicon incident already demonstrated once (`docs/progress/ugc-intelligence/ledger.md:92`) — same failure mode, different seam.

### `[CRITICAL]` 3. component-boundaries — no real cross-process transport exists for Contracts A, C, and E; every artefact/breaker bridge is fixture-only
- **Evidence:** `ArtefactWriter` (`src/ControlPlane/UgcIntelligence.Artefacts.Writer/ArtefactWriter.cs:16`) is instantiated only in `tests/Architecture/Phase8Fixtures.cs`, `ReferenceGraphTests.cs`, and `ArtefactAndEventLogTests.cs` — never in production code. Python's `pattern_library.py:117-134` and `mechanism_library.py:206-269` build only in-memory dataclasses/dicts and never write to the `<prefix>/<sha256[0:2]>/<sha256>.json` filesystem layout `ArtefactStore.cs:7-12` calls "the language-neutral layout contract." `BreakerCache`'s only two `IBreakerReader` implementations (`CalibrationMonitor`, same-process C3; `BreakerCache` itself) mean no cross-process reader exists at all — `BreakerCache.cs:31`'s own doc comment calls it "in production a proxy to C3's calibration API; a seam here," i.e., an acknowledged placeholder. No `Program.cs` exists anywhere in the repo (confirmed by glob) — no C# component is hosted as a running service. `docs/initial/integration-contract.md`'s Contract A/C/E sections (`:65-69`, `:151-154`) state these transports in flat present tense with no "unbuilt" caveat; grepping the full doc set for "not yet implemented / future work / seam" returns zero matches. As built, `CohortResolver.Resolve` has no production caller that can ever supply a non-null pattern library, so VPS can never reach `Anchored` in the shipped code, only ever advisory. Confirmed independently by a second, unplanned architecture-critic pass and the integration-contract.md depth read, which verified the "no caveat anywhere in the doc set" claim directly.
- **Fix:** Build the real writer-side (Python → shared filesystem/blob write matching the documented layout) and reader-side (C2's pattern-artefact resolution call; an HTTP/gRPC `IBreakerReader` client), with one end-to-end test starting from Python's actual serialized output rather than hand-built C# fixtures.
- **Owner:** control-plane-engineer + intelligence-plane-engineer (joint)
- **ADR:** revise ADR-0007 (or open a new ADR) to record this as a tracked, dated integration gap rather than a silent one; ADR-0007 should also state explicitly that C4 (and C2/C3, by the same argument) must not share a *host project* at runtime — the current `ReferenceGraphTests.cs` proves non-reachability between assemblies, not "not co-located in one process," which is the actual safety property ADR-0007 §5 claims.

### `[MEDIUM]` 12. measurement-discipline — mechanism auto-demotion can produce a `Mechanism` that library publish cannot serialize

### `[MEDIUM]` 13. measurement-discipline — demotion re-checks only one of the four criteria that gate promotion, so promotion and demotion can silently drift
- **Evidence:** `demote.py:66-67` re-checks only the disjoint-slice prevalence ratio; `warrant.py:159-167`'s `contrasted` promotion criterion additionally requires `mining_slice_ratio >= 2.0`, `>= 2` ordered/disjoint temporal slices, and the underlying `recurrent` floor counts. - **Owner:** intelligence-plane-engineer
