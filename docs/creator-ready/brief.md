Version: 1.0 · Date: 10 September 2026
Decision owner: Technical partner / project owner
Purpose: Assignment brief for the developer, paired with 02_Remediation_Plan.md.

Assignment

Make the existing credit-based Respin preparation journey safe, dependable and ready for observed creator testing. Fix applicable release obligations, improve demonstrated quality and handoff problems, and preserve reference breakdown. Do not rebuild the product or implement the entire launch/marketing roadmap. [P3 §§1–3; P5 §§1–4; L1 §2]

The first deliverable is T0: a reproducible baseline, current blocker register and scoped implementation estimate. Then deliver the agreed remediation in small reviewed changes, followed by real-service acceptance, observed user testing and a bounded fix/retest cycle.

This handoff was requested by the owner. It does not select a price, approve the proposed no-draft policy, authorize new processors or spending, or authorize production deployment/customer admission. Record those decisions at the affected step; do not let an unresolved commercial decision stop unrelated baseline or correctness work.

Product journey to retain

Entry

Required experience

Owned source text → approved creator context → script and filming plan.

Supported reference → evidence-bounded breakdown → optional, separately requested adaptation into the creator’s own script.

After generation: review checks → request a clearly priced revision when needed → retrieve the intended saved result → copy/export → record with the creator’s existing tools. Keep other useful, safe modes accessible. Reference-only use is valid; do not force a script purchase. [P1 §§1, 5–8; L1 §§1–2]

Instagram and TikTok remain explicit verification targets. The supplied evidence establishes autopsy/Spin foundations, not working platform-specific URL ingestion. Prove support, disclose its limits, and escalate any missing adapter as a bounded decision. Do not silently remove this route or describe transcript-only analysis as visual inspection.

What to remediate

Release obligations: inspect and close applicable admission, scoped access, billing/recovery, deletion-journal/restore, lifecycle residual, telemetry and customer-facing policy gaps. Historical open items are investigation targets—not automatically current defects. [P1 §§3, 10–11]

Quality: evaluate the current output first; improve source fidelity, creator voice, substance, spoken readability and feasible filming through the existing bounded repair path. Practical filming constraints are optional per brief, not another mandatory onboarding process. [P5 T1–T2]

Handoff: present Script, Filming plan and Checks/rationale views of the same stored result. Provide dependable copy/text/Markdown export where missing. Preserve checks, disclosures, historical output compatibility and revision lineage. Display configured charges before paid actions. [P5 T3]

Billing clarity: distinguish an existing operation’s retrieval/recovery from a deliberately commissioned new operation. Separately, prepare the proposed no-debit treatment for terminal quality refusal; implement that commercial change only after explicit approval. Autopsy outcomes need their own inspection. [P1 §§7–8; P5 T6; L1 §2]

Foundations and exclusions

Preserve approved/versioned brains, the authoritative credit ledger, scoped generation/revision records, durable attempts/checkpoints, Stripe deduplication, vendor calls outside settlement transactions, lifecycle duties and the existing repair bound. Preserve the verified-only numerical-learning correction already documented. [P1 §§2, 6–11]

Exclude recording-pack billing, A$149 pricing, bundled revisions, a full script editor, rendering, audio/video-upload expansion, scheduling/publishing, new analytics dashboards, broad discovery, provider migration, orchestration frameworks and affiliate integration. Optional follow-ups and model optimization are not prerequisites for this release. [P5 §§1, 3, 5]

Definition of completion

Deliver a reproducible candidate with executed, risk-matched tests; independent review of consequential money/data/recovery changes; accepted intended-environment journeys; truthful supported-input and charge disclosures; demonstrated deletion/restore and rollback; and a handoff ready for the first observed creators. Mark every unexecuted check NOT RUN. Distinguish implementation, local verification, real-service acceptance, deployment and customer evidence.

Engineering readiness permits the test. It does not establish lower preparation effort, actual recording, independent repeat use or renewal. Those remain the customer evidence sought by the launch pack. [P3 §§4, 6; L1 §§3–4, 7]

First developer response

Return the actual revision and preserved-work record, verified code paths, current/open/unknown obligations, Instagram/TikTok support findings, proposed change slices, estimates with uncertainty, required access/decisions and the first slice’s verification plan. Do not return a new PRD or a claim that the old snapshot proves readiness.
