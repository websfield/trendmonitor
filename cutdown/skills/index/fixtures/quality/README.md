# Quality-flag fixture corpus (Phase 2 task 7, PRD REQ-014)

Positive / negative fixture pairs for the twelve `quality-flag-kind` detectors in
`workers/indexer-python/src/quality.py`. Every clip here is **generated by FFmpeg
8.0.1 from the ingest golden set** — nothing was downloaded, and no real footage
is present. The base clips are:

| base | what it is |
|---|---|
| `data/golden-sets/ingest/clean.mp4` | `testsrc2` 640x360, CFR 30/1, 5.000 s, plus real `flite` synthesised speech at 48 kHz |
| `data/golden-sets/ingest/broll-silent.mp4` | flat colour card, static, no audio stream |

`clean.mp4` is the only base used below: it is sharp, correctly exposed, moving,
full-frame, and carries genuine speech, so every defect fixture is that clip with
exactly one thing done to it and the control is that clip with nothing done to it.
That is what makes the pair a *control* rather than two unrelated clips.

## Why two controls and not twelve

`negative-video.mp4` and `negative-audio.wav` are the negative case for **all**
twelve kinds. A defect-free clip that fires nothing is stronger evidence than a
per-kind control would be: it shows the detector for kind X is silent not only on
"footage without X" but on footage without *any* defect, which is the false
positive that actually matters. Both controls currently report **zero flags**.

## Regenerating the corpus

Run from `cutdown/`. `$V` is the shared video encode; `$A` the shared audio encode.

```bash
IN=data/golden-sets/ingest/clean.mp4
O=skills/index/fixtures/quality
V="-c:v libx264 -preset veryfast -crf 28 -pix_fmt yuv420p -r 30 -fps_mode cfr -an -t 3 -movflags +faststart -y"
A="-vn -ac 1 -ar 16000 -c:a pcm_s16le -t 2.5 -y"

# --- the controls: the base clip, re-encoded, nothing done to it ---
ffmpeg -v error -i $IN                                                            $V $O/negative-video.mp4
ffmpeg -v error -i $IN                                                            $A $O/negative-audio.wav

# --- video positives ---
ffmpeg -v error -i $IN -vf "boxblur=10:1"                                          $V $O/blur.mp4
ffmpeg -v error -i $IN -vf "crop=600:320:20+16*sin(2*PI*9*t):20+14*cos(2*PI*11*t)" $V $O/shake.mp4
ffmpeg -v error -i $IN -vf "eq=brightness=-0.55"                                   $V $O/exposure-under.mp4
ffmpeg -v error -i $IN -vf "eq=brightness=0.55"                                    $V $O/exposure-over.mp4
ffmpeg -v error -i $IN -vf "eq=brightness=-1:enable='between(t,1,2)'"              $V $O/black-frame.mp4
ffmpeg -v error -i $IN -vf "drawbox=x=128:y=72:w=384:h=216:color=gray:t=fill"      $V $O/occlusion.mp4
ffmpeg -v error -i $IN -vf "scale=640:180,pad=640:360:0:90:black"                  $V $O/poor-crop-bars.mp4
ffmpeg -v error -i $IN -vf "scale=80:46,scale=640:360:flags=bicubic"               $V $O/low-resolution.mp4

# duplicate / frozen frames: 1 s moving, 1 s of ONE repeated frame, 1 s moving.
# Built by concatenation rather than by a filter because the defect has to be
# genuinely identical frames, not merely similar ones.
ffmpeg -v error -i $IN -vf "select=eq(n\,45)" -frames:v 1 -y $O/.still.png
ffmpeg -v error -i $IN      -t 1 -an -c:v libx264 -preset veryfast -crf 28 -pix_fmt yuv420p -r 30 -fps_mode cfr -y $O/.a.mp4
ffmpeg -v error -loop 1 -i $O/.still.png -t 1 -an -c:v libx264 -preset veryfast -crf 28 -pix_fmt yuv420p -r 30 -fps_mode cfr -y $O/.b.mp4
ffmpeg -v error -ss 2 -i $IN -t 1 -an -c:v libx264 -preset veryfast -crf 28 -pix_fmt yuv420p -r 30 -fps_mode cfr -y $O/.c.mp4
printf "file '.a.mp4'\nfile '.b.mp4'\nfile '.c.mp4'\n" > $O/.list.txt
ffmpeg -v error -f concat -safe 0 -i $O/.list.txt -c copy -movflags +faststart -y $O/duplicate-frames.mp4
rm -f $O/.still.png $O/.a.mp4 $O/.b.mp4 $O/.c.mp4 $O/.list.txt

# --- audio positives ---
ffmpeg -v error -i $IN -af "volume=18dB" $A $O/audio-clipping.wav
ffmpeg -v error -i $IN -f lavfi -i "anoisesrc=r=16000:c=white:a=0.12:d=3" \
  -filter_complex "[0:a]aresample=16000[s];[s][1:a]amix=inputs=2:duration=shortest:normalize=0[o]" -map "[o]" $A $O/audio-noise.wav
ffmpeg -v error -i $IN -f lavfi -i "anoisesrc=r=16000:c=white:a=0.35:d=3" \
  -filter_complex "[0:a]aresample=16000[s];[s][1:a]amix=inputs=2:duration=shortest:normalize=0[o]" -map "[o]" $A $O/speech-unintelligible.wav
ffmpeg -v error -f lavfi -i "anullsrc=r=16000:cl=mono" $A $O/silence.wav
```

Audio fixtures are **16 kHz mono WAV, not AAC**, deliberately: `audio_clipping`
measures samples at full scale, and a lossy codec's overshoot and ringing would
mean the detector was measuring the encoder rather than the defect.

## Measured separation

Every threshold in `quality.py` was chosen from these numbers — the fire point
sits in the gap between the two measured populations, not at a remembered
"industry" value. Re-run `pytest -k coverage_matrix` after regenerating.

| kind | rule | control measures | positive measures | fires at |
|---|---|---|---|---|
| blur | `blur.laplacian_variance` | 710–822 | 3.9–4.8 | < 40 |
| shake | `shake.translation_jerk` | max 1.06 | median 23.3 | > 8.0 |
| exposure | `exposure.shadow_clipping` | 0.0022 | 0.836 | > 0.30 |
| exposure | `exposure.highlight_clipping` | 0.00002 | 0.819 | > 0.30 |
| black_or_frozen_frame | `…mean_luma` | 127 | 0.0 | < 8.0 |
| black_or_frozen_frame | `…frame_delta` | min 1.75 | 0.0 | < 0.15 |
| occlusion | `occlusion.centre_flat_cells` | max 0.50 | 1.0 | > 0.60 |
| poor_crop | `poor_crop.bar_fraction` | 0.0 | 0.494 | > 0.10 |
| low_resolution | `…high_frequency_energy` | 0.0072–0.0081 | 0.0007–0.0009 | < 0.0020 |
| duplicate_frames | `duplicate_frames.dhash_match` | 0.0 | 1.0 | > 0.5 |
| audio_clipping | `…clipped_sample_fraction` | 0.0 | 0.500 | > 0.001 |
| audio_noise | `audio_noise.noise_floor_dbfs` | −35.4 dBFS, flatness 0.13 | −22.0 dBFS, flatness 0.56 | > −30 dBFS **and** flatness > 0.20 |
| speech_intelligibility | `…speech_band_snr_db` | 15.95 dB | 0.94 dB | < 10 dB, given audible content |
| silence | `silence.frame_level_dbfs` | −66 dBFS momentary, never sustained | −120 dBFS throughout | < −50 dBFS for ≥ 1 s |

### Three findings worth keeping

1. **The textbook 8x8 dHash does not work on this control.** At 64 bits,
   consecutive `testsrc2` frames — visibly moving — hash identically, so
   `duplicate_frames` fired on every frame of the *control*. The grid is 32x32
   (1024 bits). This is exactly the failure a negative control exists to catch.
2. **Letterbox bars are not underexposure.** `poor-crop-bars.mp4` reads 50% of
   its luma at the black point purely from its bars. Exposure is therefore
   measured on the frame *interior*, after the bars are detected and removed.
3. **A silent track is not unintelligible speech.** A speech-band SNR over
   digital silence computes as 0 dB and would flag `speech_intelligibility`;
   the rule is qualified on the window actually containing audible content.

## Known gap

There is **no positive fixture for subject-clipping** (`poor_crop` where the
subject runs off the frame edge) because there is no detector for it. A
spectral-residual saliency rule was built and measured here, then removed: its
border-band ratio read 1.18 on dense `testsrc2`, 0.16 on a flat b-roll card, and
0.77 on a deliberately edge-clipped subject — no content-independent fire point
exists, so any threshold would have been tuned to one kind of footage. `poor_crop`
is covered by the framing (bar) proxy only. See `quality.py`'s module docstring.
